# M5 启动对账契约

状态：本节点本地验收通过（2026-10-03）；验收证据见 [验证记录](verification/m5-startup-reconciliation-2026-10-03.md)。完整 M5 尚未完成。

## 启动顺序与权威

停止旧任务执行器 → 检查应用库迁移 → 验证 Vault 原件、来源状态与归档日志 → 初始化同一事件循环的 LightRAG → 对账当前修订 → 启动索引/生成/问答任务。

Wiki 扫描及文件日志恢复仍可在模型不可用时运行。索引、生成与问答必须等当前启动的 Core 对账成功；读取异常不能视为索引不存在。对账失败后使用已有“重新初始化”入口重试。

## Core 检查与修复

- 按来源 UUID 游标分批检查 active、latest=current、ready 且索引任务 succeeded 的来源。排队/运行中的索引及文件任务不参加检查。
- 严格读取文档状态、完整文本、实体/关系文档清单及所属文本块；校验解析文本 SHA、processed 状态、成员清单与块父修订。检查不等于向量/图谱全部行的完整性证明，也不证明每块正文与完整文本逐字一致。普通索引管线使用位置块 ID，不能把它误当作内容哈希。
- 确定缺失或不一致时，用原有索引任务持久化 cleanup → insert 修复。写入前比较来源生命周期、latest/current、哈希、索引时间和任务更新时间；旧检查不能作用于新修订、删除后的来源或已经重试的任务。
- 排队修复时清空 current 指针，使原有证据过滤立即拒绝新答案使用该来源。保留原件、解析快照、原索引时间和已审阅 Wiki；完成相同解析内容的重索引后证据身份恢复。
- 部分损坏若无法通过上游安全删除 API 清理，任务明确失败，留待后续完整工作区重建；不直接删除图谱/向量行。
- 网络/存储读取失败：对账 unavailable，保留既有持久状态，不误排修复。

## Vault 位置检查

- active 来源只能在 Sources/Files；无当期文件意图的 deleted 来源也必须仍在该位置。
- 当期未取消归档或恢复意图允许完整目录在 Sources 或 Trash 任一位置，以支持 rename 已完成但数据库未提交的重放。
- 当期归档 succeeded 且没有恢复意图时，必须在 Trash。
- 同一来源目录同时存在、缺少修订、成员多出、哈希不符或不安全文件均拒绝启动；不猜测、不覆盖权威文件。

## 公开状态

`GET /api/v1/system/reconciliation` 返回本进程最近一次检查的 state（pending/complete/unavailable）、checked/healthy/repair_queued/skipped 计数和安全 detail。报告不返回原文、清单或模型密钥；修复工作的持久性由索引任务表承担。

完整备份恢复、应用映射恢复及损坏工作区全量重建仍是 M5 后续必需工作，不能由本节点替代。
