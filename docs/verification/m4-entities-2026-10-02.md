# M4 entity navigation — local verification, 2026-10-02

This verifies the read-only Wiki/Core mapping node against the existing synthetic acceptance Vault. It does not complete M5/M6, third-party model adapters, graph visualization or release portability.

## Implementation and review

- Exact retained evidence chunks are checked against Core `text_chunks.full_doc_id` and quote prefixes. Document `full_entities` provides candidate names; complete `entity_chunks` membership supplies associations. Graph summaries and truncated graph `source_id` are not source evidence. Names use exact UTF-8 SHA-256 identities.
- Reverse candidates use the latest `PageGenerationBinding` before an own generation manifest. Generation detail verifies all current sources and the page hash, and the service checks again after Core reads. A final Wiki read detects a concurrent edit and returns the new hash with an invalid binding or omits the reverse candidate. Read-only operations have a 60-second bound and fixed safe error responses.
- Shared runtime owns the same Core loop and installs a new mapping service on Vault replacement. No additional server, provider or dependency was added.
- Independent Python, TypeScript, general and database reviews were used. Findings fixed: generation detail does not include title; inconsistent Unicode/type bounds; missing Core truncation propagation; final-read race returning the old hash; UI rejection of valid long/multiline Wiki titles; lack of a leading chunk lookup index. All final finite reviews reported no remaining blocking findings.
